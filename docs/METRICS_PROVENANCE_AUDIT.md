# SolarSentinel AI — Metrics Provenance & Forensic Audit

## 1. Forensic Investigation Summary

This audit investigates and resolves all metric divergences between development phases (notably Phase 6 and Phase 7). 

### Key Discovery:
In Phase 6, three separate sets of numbers were computed and saved:
1. **The Production VGG16 Baseline Evaluation** (`ml/metadata/test_set_evaluation.json` & `ml/experiments/vgg16_baseline/metrics.json`):
   - Evaluated directly on the untouched 131-sample held-out split (`ml/metadata/split_manifest_70_15_15.json`).
   - **Test Accuracy:** **82.44%**
   - **Macro F1:** **0.8378**
   - **Weighted F1:** **0.8235**
   - **Physical-Damage Recall / F1:** **80.00% / 0.8000** (8/10 correctly classified)
   - **Measured Latency (Host CPU, 30 iterations):** Forward Pass: **209.1 ms**, Grad-CAM: **650.58 ms**, Total Pipeline: **859.68 ms**.
2. **The Experimental Architecture Benchmark** (`docs/PHASE6_MODEL_BENCHMARK.md` & `ml/experiments/`):
   - **EfficientNetB0 Benchmark:** Test Accuracy **84.73%**, Macro F1 **0.8418**, Weighted F1 **0.8462**, Inference Latency **118.7 ms**.
   - **MobileNetV2 Benchmark:** Test Accuracy **83.21%**, Macro F1 **0.8245**, Weighted F1 **0.8309**, Inference Latency **62.4 ms**.
   - **VGG16 Retrain with Class Weights:** Test Accuracy **88.55%**, Macro F1 **0.8912**, Weighted F1 **0.8841**.
3. **Phase 7 Display Anomaly**:
   - During Phase 7 documentation creation, numbers from the **EfficientNetB0** benchmark row in `docs/PHASE6_MODEL_BENCHMARK.md` (Accuracy **84.73%**) and preliminary uncalibrated timing runs (76.9 ms / 129.2 ms / 206.1 ms) were inadvertently entered into `README.md` and `docs/ARCHITECTURE.md` as if they applied to the production VGG16 model.
   - However, the actual production model binary (`ml/models/solar_sentinel_vgg16.keras`) and its persisted evaluation file (`ml/metadata/test_set_evaluation.json`) always retained the true **82.44%** accuracy and **209.1 ms / 650.58 ms / 859.68 ms** latency profile.

## 3. Detailed Audit Questions & Answers

1. **Which model generated each metric?**
   - **82.44% Accuracy, 0.8378 Macro F1, 0.8235 Weighted F1, 209.1ms latency:** Generated by the current production model `ml/models/solar_sentinel_vgg16.keras`.
   - **84.73% Accuracy, 0.8418 Macro F1, 0.8462 Weighted F1:** Generated by the **EfficientNetB0** benchmark experiment (`ml/experiments/efficientnetb0/metrics.json`).
   - **85.39% Accuracy:** Generated by evaluating the production model on the 178-sample validation split.
   - **84.75% Accuracy:** Generated in Phase 5 on the 177-sample initial validation split.
2. **Which dataset split generated each metric?**
   - Held-out test metrics (82.44% and 84.73%) were generated on the 131-sample test split of `ml/metadata/split_manifest_70_15_15.json`.
   - Validation metrics (85.39% and 84.75%) were generated on the validation split.
3. **Whether all metrics refer to the same model?**
   - **No.** The metrics in `README.md` (84.73%) were accidentally cited from the EfficientNetB0 comparison row in `docs/PHASE6_MODEL_BENCHMARK.md`. The actual production model is VGG16 (82.44%).
4. **Whether latency numbers were measured using the same methodology?**
   - Yes, latency measurements reflect host CPU forward pass and Grad-CAM backprop over 30 iterations. The numbers 209.1 ms / 650.58 ms / 859.68 ms are the exact verified measurements in `ml/metadata/performance_benchmark.json`.
5. **Whether the Phase 7 frontend displays metrics from the actual production model?**
   - Yes. The frontend dynamically consumes `GET /api/v1/model/metrics`, which reads directly from `ml/metadata/test_set_evaluation.json` and `ml/metadata/performance_benchmark.json`. The frontend never hardcoded 84.73%; the inaccuracy was strictly in the static Markdown files (`README.md` and `docs/ARCHITECTURE.md`).
6. **Whether any values are hardcoded in the frontend?**
   - A full repository scan confirms **zero** hardcoded performance metric numbers in `frontend/src`.
7. **Whether any values belong to a benchmark architecture instead of the production model?**
   - Yes: 84.73% accuracy belonged to EfficientNetB0 benchmark, not the production VGG16.
8. **Whether any metadata files have been overwritten or mixed?**
   - The metadata files (`test_set_evaluation.json` and `performance_benchmark.json`) are completely intact and correct. Only the markdown documentation contained transcription mix-ups.

---

## 4. Corrective Action Taken

1. Standardized `ml/metadata/production_model.json` and `ml/metadata/production_model_metrics.json` as the single authoritative registry.
2. Corrected `README.md`, `docs/ARCHITECTURE.md`, and `docs/REPRODUCIBILITY.md` to reference the genuine **82.44%** test accuracy and **209.1 ms / 650.58 ms / 859.68 ms** latency for VGG16.
3. Retained all benchmark data for EfficientNetB0 (84.73%) and MobileNetV2 (83.21%) in `docs/PHASE6_MODEL_BENCHMARK.md` with explicit architecture labels.
